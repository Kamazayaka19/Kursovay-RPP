# Электронная очередь студенческого МФЦ РГАУ-МСХА (Django)

Веб-сервис «очередь + портал услуг» по паспорту проекта и практической работе № 3.
Вырос из Streamlit-прототипа PostCode Challenge: ядро очереди (приоритет, атомарный вызов,
мягкое/немедленное закрытие окна, журнал событий) перенесено на Django ORM и дополнено
тем, что требует МФЦ.

## Быстрый запуск (Windows, PyCharm или PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py makemigrations queueapp
python manage.py migrate
python manage.py seed_demo --history
python manage.py runserver
```

Откройте http://127.0.0.1:8000/. На macOS/Linux активация: `source .venv/bin/activate`.

Демо-пользователи (пароль `demo12345`, смените перед пилотом):

| Логин | Роль | Что видит |
| --- | --- | --- |
| operator1, operator2 | Оператор | /operator/ — рабочее место окна |
| manager | Руководитель | /dashboard/ — нагрузка и показатели пилота |
| mfcadmin | Администратор | /admin/ — справочник услуг, окна, пользователи |

Свой суперпользователь: `python manage.py createsuperuser`.

Чтобы открыть с телефона в той же Wi-Fi сети: `python manage.py runserver 0.0.0.0:8000`
и зайти на `http://<IP-компьютера>:8000/`.

## Десктоп-версия (PySide6 + QML)

Та же очередь как программа для Windows/macOS/Linux. Ядро (`engine.py`, `models.py`,
`analytics.py`) общее с веб-версией, база — тот же `db.sqlite3`, поэтому сайт и программу
можно запускать одновременно: талон, взятый в программе, виден на сайте, и наоборот.

```powershell
pip install -r desktop\requirements.txt
python desktop\main.py
```

При первом запуске программа сама создаёт таблицы и демо-данные. Вкладки:

| Вкладка | Кто видит | Что делает |
| --- | --- | --- |
| Терминал | все | справочник услуг, живая очередь, запись на время, проверка талона по номеру |
| Табло | все | вызванные талоны и окна, следующие в очереди (для экрана в зале) |
| Оператор | operator1, operator2, mfcadmin | открыть окно, вызвать, принять, перенаправить, закрыть |
| Руководитель | manager, mfcadmin | показатели за день/7/28 дней, выгрузка CSV |

Вход — кнопка «Вход для сотрудников» (те же логины, пароль `demo12345`).

| Файл | Назначение |
| --- | --- |
| `desktop/main.py` | запуск: настройка Django ORM, подготовка БД, загрузка QML |
| `desktop/backend.py` | класс `Backend(QObject)` — слоты, которые вызывает QML |
| `desktop/qml/*.qml` | интерфейс: окно, 4 страницы, компонент `PrimaryButton` |
| `desktop/test_desktop.py` | самопроверка на временной БД: `python desktop\test_desktop.py` |

Сборка в один `.exe`: `pip install pyinstaller`, затем
`pyinstaller --noconfirm --windowed --name MFCQueue --paths . --add-data "desktop/qml;desktop/qml" --collect-submodules queueapp --collect-submodules config desktop/main.py`.

## Мобильное приложение для студента (Flet)

Папка `mobile/`. Это клиент: данные хранит сервер (этот же Django-проект), а приложение
обращается к нему через JSON-API. Поэтому талон, взятый с телефона, сразу видят оператор
в десктоп-версии и табло.

Что умеет: справочник услуг с ожиданием, «встать в живую очередь» (нужен код с QR-таблички,
демо `mfc-stand-demo`), запись на время, «Мой талон» со статусом каждые 5 секунд,
вибрация и окно «Вас вызывают», «Я на месте», отмена талона.

Показ на защите:

1. На ноутбуке запустить сервер для всей Wi-Fi сети: `python manage.py runserver 0.0.0.0:8000`
   (узнать IP ноутбука: `ipconfig`, строка IPv4, например 192.168.1.5).
2. Проверить без телефона: `pip install -r mobile\requirements.txt`, затем `flet run mobile\main.py`.
3. На телефоне — приложение **Flet** из Google Play / App Store, затем `flet run --android mobile\main.py`
   (или `--ios`) и отсканировать QR-код из консоли. Телефон и ноутбук в одной Wi-Fi сети.
4. В приложении: «Настройки» → адрес `http://192.168.1.5:8000` и код `mfc-stand-demo` → «Сохранить».

Сборка APK: `cd mobile`, затем `flet build apk` (первый раз сама скачает Flutter и Android SDK,
это долго). Готовый файл — `mobile/build/apk/`.

API сервера (`queueapp/views.py`, раздел «JSON API для мобильного приложения»):

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/api/services/` | справочник услуг с очередью и прогнозом |
| GET | `/api/services/<id>/slots/` | дни и свободные слоты записи |
| POST | `/api/services/<id>/live/` | талон в живую очередь (`key` — код со стойки) |
| POST | `/api/services/<id>/book/` | запись на слот (`slot` — время ISO) |
| GET | `/api/ticket/<token>/` | состояние талона |
| POST | `/api/ticket/<token>/checkin/`, `/cancel/` | «Я на месте», отмена |

Самопроверка API и клиента: `python mobile\test_api.py`.

## Обновление с прошлой версии

Распакуйте архив поверх старой папки с заменой файлов (база `db.sqlite3` и `.venv` не затрутся), затем:

```powershell
python manage.py makemigrations queueapp
python manage.py migrate
python manage.py seed_demo --update
```

## Сценарий показа (≈3 минуты)

1. **Студент** — главная: справочник услуг с ожиданием по каждой. Карточка услуги:
   что взять с собой, срок готовности, кнопка «Заказать в личном кабинете» для онлайн-услуг.
2. **Запись на слот** — «Записаться на время» → талон со статусом «Записан».
   Кнопка «Я на месте» доступна за 30 мин до слота и до 10 мин после.
3. **Живая очередь** — откройте /qr/ (QR-табличка для стойки) и нажмите
   «открыть ссылку QR в этом браузере» — это эмуляция скана. Теперь на карточке услуги
   есть «Встать в живую очередь».
4. **Оператор** (вторая вкладка/браузер, operator1) — выбрать окно → отметить услуги →
   «Открыть окно» → «Вызвать следующего». У студента статус меняется сам,
   приходит уведомление браузера «Вас вызывают».
5. **Табло** /board/ — для экрана в зоне ожидания.
6. **Руководитель** (manager) — /dashboard/: среднее/максимальное ожидание, доля
   вызванных в своё время, ушедшие в ЛК, загрузка по часам, окнам, услугам; выгрузка CSV.
7. **Администратор** (mfcadmin) — /admin/: правит справочник и окна без программиста.
8. Переключатели в шапке: RU/EN и «Крупный шрифт и контраст».

## Что из ПР № 3 и паспорта реализовано

| Требование | Где в коде |
| --- | --- |
| Справочник услуг с регламентами и документами | `Service`, `home.html`, `service.html` |
| Отметка «можно онлайн» + учёт переходов в ЛК | `go_lk` → событие `lk_redirect` → дашборд |
| Запись на временной слот + QR-талон | `engine.slots_for/create_booking/check_in`, `/qr/` |
| Прогноз ожидания | `engine.estimate_wait` (позиция × норматив / открытые окна) |
| Уведомление о приближении очереди без SMS | `app.js` (Notification API, вибрация) |
| Талон без ФИО, телефона, зачётки (сторона № 13) | в модели таких полей нет |
| Роли оператор / администратор / руководитель | группы Django, `roles.py` |
| Аналитика по окнам и услугам, без рейтинга сотрудников (сторона № 5) | `analytics.py` |
| Кнопка «зафиксировать проблему» | действие `issue` у оператора |
| Резервный режим с бумажными талонами (сторона № 4) | «Клиент без электронного талона → Принять сейчас» |
| Режим доступности и английский интерфейс (стороны № 14, 15) | `i18n.py`, класс `.a11y` |
| Запуск одной командой, health-check, секреты вне кода, логи (сторона № 11) | `docker-compose.yml`, `/health/`, `.env.example` |
| Нет двойного назначения талона | транзакция SQLite `IMMEDIATE` + условный UPDATE в `engine.call_next` |
| Рестарт без потерь, талон не теряется при обрыве связи | SQLite, токен в URL и сессии |

## Правила приоритета

Все коэффициенты — в `config/settings.py`, словарь `QUEUE`:
вес канала (запись 0, QR 10), «старение» 0,5 за минуту ожидания, окно явки записи ±10 мин,
бонус записи 100, длина слота 15 мин, рабочие часы и обед, за сколько человек предупреждать.

## Боевой запуск на сервере вуза

```bash
cp .env.example .env      # заполнить секреты и адреса
docker compose up -d --build
docker compose exec web python manage.py seed_demo
```

Резервная копия: файл `/data/db.sqlite3` в томе `mfc_data`
(например, ежедневно `docker compose exec web python manage.py dumpdata > backup.json`).
HTTPS обеспечивает обратный прокси вуза (nginx).

## Ограничения прототипа

- Интеграции с 1С:Университет ПРОФ и документооборотом нет — только ссылка на ЛК (за границами пилота).
- Уведомления работают, пока вкладка талона открыта; push при закрытом браузере — следующий шаг.
- Группа «Администратор» может управлять пользователями в /admin/ — назначайте её только доверенному сотруднику МФЦ.
- Страницы оператора и руководителя — только на русском; RU/EN переключает клиентскую часть.
- Справочник в `seed_demo` примерный — перед пилотом его наполняет администратор МФЦ.
- Обновление статуса — опрос сервера раз в 5 секунд (без WebSocket и Redis — осознанное упрощение).
